# 动态 Turn Trace 第一版

状态：已实现。Web 工作台默认持续采集，语义分析改为手动选择 Turn 后触发。

## 使用

1. 启动工作台和 Claude，正常输入任务。
2. 点击终端页「查看动态执行图」。当前轮先展示事实 Event，顶部显示执行或收尾状态。
3. 点击「语义分析」，选择一个或多个 Turn，再点击「开始语义分析」。完成轮次只生成事实快照，不会自动调用模型；执行中也可显式分析当前快照。
4. 分析完成后自动补充行为摘要、四类行为角色和审查通过的逻辑关系。
5. 状态详情显示每轮执行状态、分析进度、版本与错误；失败时重新打开同一「语义分析」入口，选择该轮继续。
6. 需要全部轮次时在同一入口中「全选」；需要重新判断已分析轮次时勾选「重新评估已分析轮次」。

原始日志随采集版本刷新，保留查看模式和分页。四泳道语义聚合仍使用原有手动生成入口；本版手动 Turn 分析面向 Agent 详细执行工作流。

## 采集与恢复

- `LiveTraceService` 有独立采集和分析任务，默认每秒轮询；Hook 只记录原始事件，不执行 AI。
- 以二进制读取新增内容，只有完整换行记录进入事务。未完成的末行保留在源文件，下次从提交游标重读；中文多字节切断不会提前解码。
- SQLite 同事务提交采集记录和文件游标。JSON 投影在事务后生成；宕机后根据采集数量恢复投影。
- 文件身份、读取偏移及末端锚点识别替换、截断和截断后重新增长。UUID 加内容去重，保留同 UUID 的不同内容；无 UUID 的记录保留来源版本与物理行号。
- SQLite 原始采集记录包含来源版本和源行号；原始日志投影的行号连续，Event 回溯指向该投影。
- 完整但非法的 JSON 行保留为解析失败记录，不阻断后续行。
- 现有事实派生在新增完整记录后运行；首版不改写为逐 Event 增量解析器。

## Turn 边界

使用现有真实人类输入识别 Turn，结合 `UserPromptSubmit` 和主 Agent `Stop`、`StopFailure`、`SessionEnd`。

- `Stop` 是收尾候选。最终回答已采集、对应文本或结束标记确认、轮内事实短暂稳定，且末轮无未完成 JSON 行时，才发布固定分析快照。
- 文件不增长、工具返回、`SubagentStop` 均不独立证明主轮次成功。
- 新提示尚未写入时，其 Stop 不会关闭上一轮。
- 失败、中断单独标记；下一轮已开始却没有成功结束依据的上一轮，按部分执行保存。
- 通过原始 `tool_use_id` 将迟到子任务结果归还发起轮次；更新该轮版本，不移入最新轮次。
- 用户中断如果没有明确控制记录，需等下一轮输入或会话退出才能确认，期间仍显示执行中。
- Stop 是结束候选，不代表能观察到其他插件的全部决策。若后续继续执行并产生新事实，会使旧快照失效并生成新版本。

Hook 字段依据：[Claude Code 官方 Hook 文档](https://code.claude.com/docs/en/hooks#stop)。

## 逐轮分析与存储

会话目录：

```text
live/capture.sqlite3
live/state.json
live/turns/<turn_id>/v0001/<session_id>/
  manifest.json
  derived/observer_trace.json
  derived/events.jsonl
  derived/event_workflow.json
  derived/event_semantics.jsonl
  derived/event_workflow_stages/...
```

- 六类 Event、摘要批次、13 类关系表、关系复核、四类行为角色全部复用现有 `run_event_workflow`。
- 每轮快照只包含本轮 Event 与轮内规则关系；最近三轮用户任务和已报告结果作为有限的历史理解上下文，不能作为本轮引用证据。
- 快照同时记录执行完整性；角色分类基于本轮已知事实。
- 下一轮追加记录不改变旧快照的源哈希。迟到或修订事实生成新版本，旧版本文件保留。
- 每个会话串行分析，进程锁避免多 Web worker 重复调用；重启可恢复排队和运行中任务，模型阶段检查点继续复用。失败保持 partial，显式选择后重试。仅含 analysis_requested 标记的用户选择任务会执行；旧的自动队列不会继续调度。
- 未配置模型时保存事实图并等待配置。沿用现有语义 API、模型和思考强度配置。
- 既有历史轮次不因恢复会话而自动批量发送模型，可继续使用全会话分析入口。
- 发布结果只组合已完成、与当前事实匹配的轮次。跨轮保留事实规则关系，本版不自动推断跨轮 AI 关系。
- 页面刷新不卸载整个画布，不主动重置当前视角；节点尺寸变化仍可能带来局部布局调整。

API：`GET /api/observations/{id}/live`、`GET /live/event-workflow`、`POST /live/analyze`（turn_ids、force）。旧 retry 接口保留兼容。

## 验证

测试覆盖 UTF-8 半行、持久化后重启、文件替换与截断、回放去重、非法 JSON、投影行号、Stop 早到、重复结束、子 Agent 边界、成功/失败/中断、下一轮追加不失效、迟到结果新版本、旧任务完成不能覆盖新版本、失败重试，以及 Web 后台在终端未退出时采集和发布结果。

另有模拟模型测试从 Turn 快照完整运行现有六类 Event 语义管线；前端测试验证逐轮部分覆盖合法、普通文件导入仍要求完整覆盖。

## 连续追问与终端尺寸修复

- 优先将 Hook 的 `prompt_id` 与 transcript 的 `promptId` 关联；同一提示附加上下文时重复触发 `UserPromptSubmit` 不再丢失归属。
- 自动通知循环仍归属于其记录位置对应的人类 Turn；新的内部 prompt ID 不新增人类任务，延迟到达的 Stop 按 ID 归还正确轮次。旧版本没有 transcript prompt ID 时，保留文本匹配并记住 Hook ID。
- xterm 在网格尺寸稳定 120ms 后才调整并通知后端，重复尺寸不再发送；后端也跳过已生效的 PTY 尺寸，防止重复 SIGWINCH 触发 Claude 重绘。
- 终端外层承担内边距，尺寸测量针对无内边距的实际容器，避免把内边距计入可用行列而产生溢出反馈。

## 版本队列与进度

- 后台在阶段切换、模型调用前和重试进度回调时检查版本。过期版本停止后续调用并保留已验证检查点，再处理当前版本；已经发出的单次网络请求需要返回或超时后才能释放线程。
- 不同版本之间可复用相同模型、思考强度及相同摘要输入的缓存。仅 Turn 的结束完整性更正不会重做逐 Event 摘要；事件事实、相关上下文发生变化时仍重新摘要，关系审查与角色分类按新版本重新评估。
- 状态接口增加 `active_analysis`，明确当前实际执行的版本、阶段、百分比。页面不会只显示新版本排队而隐藏旧版本仍在执行的事实。
