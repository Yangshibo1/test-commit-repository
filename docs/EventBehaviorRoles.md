# Event 行为角色分类

当前规范：`event-workflow/0.3`。替换旧版核心/支撑/背景三级评级。
六类原始 Event 类型保持不变；行为角色是 AI 对任务作用的派生解释，不是重要性的高低排序。

| level | 展示名称 | 成立条件 | 不应归入的情况 |
| --- | --- | --- | --- |
| `key_decision` | 关键决策 | 确立主要目标、范围、分析方法、路径或判断依据，对后续行动有实质影响 | 常规选择文件、调用工具、泛化计划 |
| `normal_execution` | 正常执行 | 沿既定方向进行读取、清洗、代码运行、绘图、验证、协调、准备或状态反馈 | 已满足其他三类条件的行为 |
| `key_turning_point` | 关键转折 | 异常、发现、反馈或验证使计划、方法、结论或执行状态发生实质变化 | 普通报错、原路径自动重试、预期验证通过 |
| `key_result` | 关键结果 | 已产生或明确报告直接回答任务问题的结论、重要分析发现、验证结论或交付成果 | 普通中间输出、生成承诺、工具成功、空泛完成声明 |

每个 Event 只给一个主类别。若多个条件同时成立，优先级为关键转折 → 关键决策 → 关键结果 → 正常执行。
这一优先级解决分类冲突，不表示视觉权重或价值排序；理由保留该 Event 的其他实质作用。
关键转折的理由应说明发生了什么变化。关键结果区分实际执行、明确报告和计划/请求，不将未核实报告包装为已验证成果。
资料不足时保守归正常执行，使用低置信度和理由说明缺口。不按邻居数量、工具类型、状态或最终响应标记自动分类，也不限定比例。

## 处理与产物

在行为摘要和独立关系审查后，使用全部任务上下文、全部 Event 摘要、规则关系及 accepted 逻辑关系分类。
邻居数量只辅助解释；parent/next、候选或被拒绝的逻辑关系不计入邻居依据。
输出字段继续使用 `event_importance[].level`，以兼容既有 JSON 容器，但 0.3 的值只能来自上表。
每条还保留 reason、confidence、related_event_ids 和代码计算的 neighbor_counts。
引用只能指向规则或 accepted 逻辑关系的直接邻居。置信度 high/medium/low 表示判断把握程度，与类别分开。
代码校验一一覆盖、枚举、理由和关联 ID，不证明模型的语义判断正确。

## 展示与旧版兼容

关键决策、关键转折和关键结果均使用完整卡片，靠近轮内中轴；正常执行使用紧凑卡片，分布在两侧。
没有关键角色的轮次，以正常执行节点组成展示主干。全部 Event 保留，轮次与事实关系不变。
类别名称使用不同颜色；现有连线避障、关键实线和辅助边缘虚线规则继续适用。

0.1/0.2 文件仍可读取，原三级标签显示“旧版”，不自动转换为新角色。
点击“按新分类生成”后由 AI 重新分类，模型仍为 gpt-6.1-sol、中思考强度。
版本变化使旧分类缓存失效；满足模型、请求及验证条件的行为摘要可复用。
历史派生结果在覆盖前归档，原始 Transcript、Event 和规则关系不改写。
