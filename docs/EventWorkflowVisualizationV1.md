# Event 主线视图与固定列布局

状态：实验记录，页面已改为 [按 Turn 纵向展示](EventWorkflowTurnView.md)，以下描述不再是当前默认 UI。
该实验只消费现有 Event、重要性和关系结果，
不发起新的 AI 请求，也不改写原始事件或关系。

## 两种阅读模式

- **任务主线（有 AI 结果时默认）**：保留核心 Event、用户要求、最终回复，以及关键纠错、
  验证、授权、替代、汇合关系涉及的支撑 Event 和逻辑分支/汇合连接点。
  其他事件按拓扑阅读顺序、轮次和执行者收进过程组。
- **完整执行图**：显示全部原有可见 Event 和合并后的执行关系。无 AI 结果时默认使用此模式。

完整目录始终列出全部可见 Event。定位被折叠事件时自动展开所属组；点击过程组可浏览成员，
点击展开按钮恢复原始节点与组内连线。展开保持当前视角与列归属，为新增内容调整后续所需空间。
候选/拒绝的逻辑关系仍仅在详情中展示，不参与布局或重要性。

过程组是展示容器，不是新 Event，也不是 AI 语义阶段。组标签仅按已有事件类型粗分为
输入准备、调用、系统记录或执行协调，不生成分析阶段标题。

## 关系与分组

用既有无环关系计算稳定的拓扑顺序，同层按 sequence/event_id 排序。
连续且属于同一轮次、执行者列的非保留事件收为一组，避免把跨关键节点的路径整体收缩成环。

主线保留逻辑关系，并从相邻任务锚点间选择已有最短执行路径作为辅助。
过程组补充实际边界关系；展开时恢复涉及成员的执行连线。
一条连线可汇总多个同方向、同来源种类的原始关系，关系详情列出真实端点。
不生成“核心 A → 核心 B”的假直接依赖，也不将记录顺序升级为逻辑关系。

折叠端点参与的逻辑边明确标为组内联系，虚线表示聚合/顺序/低置信度。
点击线上的类型标签或线条，可查看原关系、连接依据、审查意见与原始记录。

## 固定列与连线

- 主流程位于中央：任务锚点沿依赖与记录顺序纵向排列。
- 输入、必要支撑和常规过程位于左侧；独立验证支撑有相应右侧列。
- 有明确 subagent 执行者或 subagent_result 的节点进入固定子任务列，按首次出现顺序编号。
  不仅凭一个 task_id 就把主 Agent 的常规任务管理操作当作独立 Agent 分支。
- 同一列按稳定顺序排列；拓扑父节点决定最低行号。位置表示阅读顺序，不声称所有操作串行执行。
- 跨步、跨列关系通过列间通道走线，短边直接连接。图中仅画真实关系，列中的淡色引导线是阅读辅助。

主线默认视角优先聚焦前两个主流程核心事件，避免问候和准备记录占据首屏；列标题固定显示。
完整图从主流程开头阅读。可拖拽、缩放、通过目录定位、定位核心起点或查看全图。
详情默认收起，文件产物按需显示。隐藏事件产生的文件仍可关联到其过程组，明确标注组内生成/修改。
窄屏将次要操作收进「更多」，给画布保留空间。

## 已验证范围

- 现有 78 Event 会话：主线显示 17 个事件、折叠 61 个事件为 12 组；当前关系结果下连线从完整图的 95 条降至 28 条。
- 人工演示 20 Event：默认显示 8 个事件、其余 12 个收为 5 组；可展开为原始 Event，或直接切换完整图。
- 覆盖完整事件归属、真实关系保留、分组无假快捷边、展开原端点、列位置稳定、子任务列、
  无关系任务不造依赖、原始会话降级，以及 DOM 操作与响应式检查。

当前不会重新评估重要性，也不自动纠正旧关系结果。主线质量仍依赖原始标注；
固定列是阅读布局，并非按实际持续时间缩放的时间轴。
