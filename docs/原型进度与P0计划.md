# OpenTrace 原型进度与 P0 计划

## 1. 当前结论

OpenTrace 已经完成设计定型以及存储、CLI 和 Claude Plugin 骨架，但还没有形成可以稳定使用的
端到端 MVP。

当前定位：

```text
设计基本完成
SQLite和CLI原型可测试
真实Claude Code记录闭环尚未成功
规范化JSON、DAG和前端尚未接入
```

本阶段继续坚持个人系统边界。开发只优先服务两个目标：

1. 完整记录以语义 Step 为颗粒度的 Agent 数据分析 workflow。
2. 约束 Agent 按照可记录、可解释且颗粒度合理的方式进行分析。

## 2. 已完成内容

### 2.1 产品和数据设计

- OpenTrace 只记录和校验，不执行数据分析。
- Claude Code 独立负责读取数据、编写程序、选择方法和解释结果。
- Step 表示独立分析目标，不按命令、脚本、重试或临时文件拆分。
- 文件血缘当前限定到文件版本级。
- 人工指导、规划建议和异议不直接成为 Step。
- 对外 JSON 字段和内部工作流程约束已经形成独立设计文档。

## 3. 真实端到端验证结果

最近的真实 Run 已经证明以下能力有效：

- Run创建；
- Claude session绑定；
- 初始输入文件记录；
- SHA-256计算；
- SessionStart Hook；
- 部分工具门禁；
- 失败事件诊断；
- JSON导出。

但没有形成成功 workflow：

```json
{
  "plan": null,
  "steps": [],
  "status": "active"
}
```

失败原因：

1. Claude自动生成`cd "project" && python -m opentrace.agent_cli ...`。
2. 当前门禁拒绝所有包含`&&`和换行的命令。
3. 合法`set-plan`和`start-step`被误拦截。
4. `PowerShell`未被Hook覆盖。
5. Claude通过`PowerShell`读取数据并完成分析。
6. 实际分析没有进入语义Plan和Step。

所以当前只能认定为“可单元测试的技术原型”，不能认定为“可稳定使用的MVP”。

## 4. 主要遗留问题

### 4.1 运行时门禁

- 合法记录命令带`cd ... &&`时被误拦截。
- 多行JSON payload被误拦截。
- `PowerShell`未进入门禁。
- 当前工具短名单可能遗漏Web、子Agent和未来新增工具。
- 未知实质性工具可能形成旁路。
- 记录命令失败后Claude可能尝试寻找替代工具继续分析。

### 4.2 Stop和Run完成

- Stop只检查active Step和待处理人工输入。
- 没有强制要求存在Plan。
- 没有强制要求至少完成一个Step。
- 没有强制要求执行`finish-run`。
- 没有检查关键门禁旁路或记录器错误。
- Claude可能输出最终答案而Run仍为`active`。

### 4.3 最终字段尚未落地

当前代码仍使用旧字段：

```text
step_type
expected_output_roles
operation_types
parameters
algorithms
processing_result对象
analysis_conclusion对象
output role
structured_summary
```

需要迁移到：

```text
operation.summary
operation.commands
operation.programs
result_summary
analysis_conclusion字符串或null
```

文件大小、完成条件和原始事件可以继续保留在内部SQLite，但不进入对外JSON。

### 4.4 Plan与Step约束

当前只验证`node_id`存在于最新Plan，没有：

- 在Step上保存`plan_version`；
- 校验Plan依赖是否已由completed Step满足；
- 强制依赖变化前修订Plan；
- 防止Plan Revision隐藏已完成历史；
- 根据Plan Revision自动推导实际Step依赖。

### 4.5 规范化导出

当前导出混合了运行状态和诊断日志，尚未实现：

```text
schema_version
run
plan_revisions
steps
human_interventions
file_lineage
```

同时存在：

- 只导出最新Plan；
- `payload`和`payload_json`重复；
- 原始Hook事件混入语义记录；
- 没有自动刷新规范化JSON；
- 没有显式文件血缘派生。

### 4.6 自动观察

尚未实现：

- 从Bash和PowerShell提取真实分析命令；
- 过滤OpenTrace自身记录命令；
- 自动识别实际Python程序；
- 将程序和命令规范化到active Step；
- 自动发现程序内部产生的输出文件。

### 4.7 人工介入

已经有捕获、分类和apply骨架，但尚未完整实现：

- 自动关联介入发生时的active Step；
- 自动关联当时Plan Revision；
- 普通交流不进入最终JSON；
- challenge触发验证或纠正Step；
- 真实Claude端到端闭环。

### 4.8 DAG与前端

尚未实现：

- 从规范化JSON生成DAG；
- Step、文件和人工介入节点；
- input、output、depends_on和influenced边；
- `dag.json`；
- 新Run JSON前端解析；
- 以`path + sha256`区分文件版本；
- 根据Step sequence和DAG边布局。

当前前端仍读取旧版多文件PROV格式，并依赖`node_01`等文件名布局。

### 4.9 新旧系统并存

仓库同时存在旧`tracker/prov_dag/step_details/mcp_server`与新
`workflow_store/agent_cli/plugin_hook`。

后续规则：

- 新`workflow_store`是唯一事实来源；
- 旧PROV代码只作为兼容适配器；
- 不继续扩展旧记录接口；
- DAG和旧文件格式从新规范化JSON派生。

## 5. P0范围

P0只完成真实记录闭环，不包含DAG和前端迁移。

### P0-1 记录命令安全识别

- 允许单个直接记录命令。
- 允许`cd 当前项目 && 单个记录命令`。
- 允许单引号JSON payload内部换行。
- 拒绝其他项目目录。
- 拒绝追加分析命令、管道、重定向和命令替换。
- 对payload进行JSON和action校验。

### P0-2 工具门禁覆盖

- 加入PowerShell。
- 覆盖Web、子Agent和其他实质性工具。
- 未知工具默认按安全分类处理。
- Hook失败时fail-closed。
- 增加旁路审计事件。

### P0-3 最终字段迁移

- SQLite支持`plan_version`。
- Step迁移到`result_summary`和字符串`analysis_conclusion`。
- Agent不再提交算法、参数、操作类型和输出角色。
- 命令和程序来自Hook自动观察。
- 对外导出隐藏内部控制字段。
- 保留兼容迁移，避免已有数据库无法打开。

### P0-4 Plan–Step强绑定

- 每个Step对应当前Plan Revision中的Node。
- Step保存`plan_version`。
- Node依赖必须由completed Step满足。
- 依赖或目标变化必须先创建Plan Revision。
- 已完成Step不允许被后续Plan隐藏。

### P0-5 Stop和finish-run

- 无Plan时禁止结束。
- 没有completed Step时禁止结束。
- active Step未完成时禁止结束。
- 人工输入未解决时禁止结束。
- 没有成功`finish-run`时禁止正常结束。
- 存在关键一致性错误时`finish-run`失败。

### P0-6 端到端验证

至少验证：

```text
创建Run
→ Claude提交Plan
→ 启动Step 1
→ 读取声明输入
→ 完成Step 1
→ 启动并完成Step 2
→ finish-run
→ 导出规范化JSON
```

同时验证：

- PowerShell无法绕过。
- 无active Step的Read/Bash被拒绝。
- 非法记录命令无法绕过。
- Stop不能提前结束。
- 导出不包含原始诊断日志和已删除字段。

## 6. P0验收标准

P0完成必须同时满足：

1. 当前兼容网关下至少完成一次真实Claude Code Run。
2. Run最终状态为`completed`。
3. 至少记录两个completed语义Step。
4. 每个Step能够定位到Plan Revision和Node。
5. 文件输入SHA-256正确。
6. 命令和程序来自真实Hook事件。
7. 输出符合[记录字段设计.md](记录字段设计.md)。
8. 无active Step时无法读取或执行分析。
9. PowerShell和子Agent不能形成旁路。
10. 全部记录器测试通过。

## 7. P0之外

以下内容明确不属于P0：

- DAG Projector；
- 前端读取`run.json`和`dag.json`；
- 旧PROV格式适配器；
- 多用户和权限；
- 云同步；
- 审批流；
- 字段级或item级血缘；
- 通用多Agent平台适配；
- 前端整体重构。

P0完成后再进入规范化DAG和前端接入阶段。

## 8. 2026-07-28 P0实施结果

### 8.1 已完成

- 记录命令支持当前项目的`cd ... &&`前缀和多行JSON，同时拒绝命令拼接与跨项目目录。
- 所有未知工具默认进入门禁；PowerShell、Web和子Agent不能绕过active Step约束。
- Plan只保留`node_id`、`objective`和`depends_on`，并校验未知依赖、自依赖和循环依赖。
- Step保存启动时的`plan_version`，只有依赖节点已有completed Step时才能启动。
- 已经开始的Node不能被后续Plan删除，也不能修改其目标或依赖来重写历史。
- Step输入只能是Run声明输入或之前completed Step的输出文件版本。
- Claude只提交`operation_summary`、`result_summary`、字符串或null结论，以及必要的输出路径。
- 命令和程序路径从真实PostToolUse事件自动归集，OpenTrace记录命令被排除。
- 人工介入自动关联发生时的active Step和Plan Revision；普通交流不进入最终JSON。
- Stop和`finish-run`已覆盖Plan、active Step、未完成Node、人工输入和Run最终状态。
- `finish-run`成功后自动生成规范化workflow JSON。
- 旧SQLite数据库通过增量加列迁移，不删除已有历史。
- 现有记录器测试已同步到新字段接口；本轮不再增加独立端到端测试，由用户执行真实Claude手动验收。
