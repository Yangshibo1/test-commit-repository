# OpenTrace Frontend Layout Description

## 修复前的布局问题

```
┌─────────────────┐
│   MC2 data.json │ ←── (向右延伸) ────→ ┌──────────────┐
└─────────────────┘                          │  n1 output  │
                                              └──────────────┘
```

**问题**：
- Handles位置：左侧输入，右侧输出
- 边路径：贝塞尔曲线从右侧退出，向右延伸后再向下
- 结果：边看起来向右延伸，不符合自上而下的流程

## 修复后的布局

### Handles位置
```
┌─────────────────┐
│    ▲ (输入)     │ ← 从上方接收边
│                 │
│    Node         │
│                 │
│    ▼ (输出)     │ → 向下方发送边
└─────────────────┘
```

### 分层布局
```
Row 0: ┌────────┐  ┌────────┐
       │ MC2    │  │org     │
       │ data   │  │chart   │
       └────▲───┘  └────▲───┘
            │            │
            └────────────┘ (边从底部向上延伸到下一行)

Row 1: ┌────────┐  ┌────────┐
       │ n1     │  │n1      │
       │ output │  │agent   │
       └────▲───┘  └────▲───┘
            │            │
            └────────────┘

Row 2: ┌────────┐  ┌────────┐
       │ n2     │  │n2      │
       │ output │  │agent   │
       └────▲───┘  └────▲───┘
```

## 边的行为

### 同行内连接
- 两个节点在同一行时：边直接从左到右
- 路径：直线

### 行间连接
- 上行节点输出 → 下行节点输入
- 路径：从源节点底部直接到目标节点顶部
- 不再向右延伸

### 边类型
- `process` 边：灰色，直线
- `output` 边：加粗，橙色
- ~~`wasDerivedFrom`~~：已移除

## 布局参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 节点宽度 | 220px | 每个节点的固定宽度 |
| 行高 | 140px | 行与行之间的垂直距离 |
| 节点间距 | 96px | 同行内节点之间的水平距离 |
| 行间距 | 40px | 行与行之间的额外间距 |

## 修复总结

1. **Handles位置**：从左右改为上下
   - Target: Position.Top (顶部接收输入)
   - Source: Position.Bottom (底部发送输出)

2. **边路径**：使用直线而非贝塞尔曲线
   - defaultEdgeOptions设置type为'default'
   - 边直接从底部到顶部，无横向延伸

3. **wasDerivedFrom边**：已完全移除
   - 减少视觉混乱
   - 从120条边减少到76条边

## 预期效果

- ✅ 边从上到下垂直流动
- ✅ 无向右延伸的横向弧线
- ✅ 清晰的数据流层次结构
- ✅ 易于追踪的处理链路
